# GenomeX vs CheckM2

CheckM2 estimates completeness and contamination with a machine-learning model over a reference proteome database. GenomeX uses BUSCO odb10 single-copy markers plus tetranucleotide composition. The two are not expected to produce identical numbers, and identical numbers would be suspicious. This page separates what must agree from what need not.

72 genomes compared, scanned against `burkholderiales_odb10` (688 markers). Generated by `bench/compare_to_checkm2.py`.

## What a 5.5x deeper marker set bought, and what it did not

This page repeats `benchmark-contamination.md` with one change: the same 72
genomes, scanned against `burkholderiales_odb10` (688 markers) instead of
`bacteria_odb10` (124). Every genome in the collection is a member of the
Burkholderiaceae, so the deeper set applies. The lineage is a CLI argument;
GenomeX does not infer it.

The motivation was a resolution argument. One duplicated marker out of 124 is
0.81% of the core, so detecting 5% contamination through marker duplication
needs roughly six duplicated markers, and observing one is equally consistent
with a clean genome. At 688 markers the same step is 0.15%.

On constructed truth the argument holds. `bench/mixture_ladder.py` splices
fragments of one genome into another at a known share of the total, and
genome-level detection went from 0/4 pairs to 4/4 at 2% donor, and 3/4 to 4/4 at
5%, with the 0% controls staying clean in all four pairs. Details in
[`benchmark-mixture.md`](benchmark-mixture.md).

**Against CheckM2 it bought nothing.**

| | `bacteria_odb10` (124) | `burkholderiales_odb10` (688) |
|---|---|---|
| genomes flagged of 72 | 9 | 9 |
| recall at CheckM2 >= 5% | 0.00 (0/4) | 0.25 (1/4) |
| precision at CheckM2 >= 5% | 0.00 | 0.11 |
| corr(cross-contig duplication %, CheckM2 %) | -0.026 | 0.161 |
| completeness mean abs difference | 0.55 pt | 0.63 pt |

The same three genomes are missed, and they are missed for the same reason.

Those flag counts and the 124-marker recall are lower than the figures this page
carried at v0.2.0 (13 and 11 flagged, recall 0.25 under both sets). The
sole-copy rule described in `benchmark-fragmentation.md` removed a contamination
arm that fired on 12.5% of shreddings of finished genomes, and it took
`GCF_009362735.1` with it at 124 markers. At 688 that genome is still called
`likely`, which is the one place in this comparison where the deeper set now buys
something the shallow one does not.

## The two tools are not measuring the same thing

The three genomes CheckM2 puts above 5% duplicate almost none of the
single-copy core, under either marker set:

| genome | CheckM2 | cross-contig duplication, 124 | 688 | suspect contigs | replicon groups |
|---|---|---|---|---|---|
| GCA_000519245.1 | 9.35% | 0.81% | 0.44% | 0 | 18 |
| GCA_038900585.1 | 5.66% | 0.00% | 0.58% | 0 | 7 |
| GCA_001725945.1 | 5.17% | 0.81% | 0.15% | 0 | 7 |

Those duplication figures sit at or below the ~1% that finished reference
genomes in this collection show from ordinary cross-replicon paralogy alone.
Across all 72 genomes the cross-contig duplication rate never exceeds 1.60%,
while CheckM2 reaches 9.35%, and the two correlate at 0.161.

This is no longer a story about resolution. Five percent of a foreign genome is
now expressible — 34 of 688 markers — and it is not there.

The mixture ladder is what makes that statement worth something. It shows this
detector, on this collection, catches a genuine 2% foreign genome in 4/4 pairs
and a 5% one in 4/4. When a second organism really is contributing its share of
the single-copy core, the marker channel says so. In these three genomes it does
not.

What GenomeX does find in all three is compositionally distinct sequence: 18, 7
and 7 candidate replicon groups. Distinct sequence carrying none of the
universal core is what a plasmid, a prophage or laterally acquired material
looks like, and it is also what a low-abundance contaminant that happens to
carry no core genes looks like. Composition cannot separate those two readings;
coverage depth can, and this pipeline has no read input.

So the honest statement is not "GenomeX missed three contaminated genomes", and
it is not "CheckM2 is wrong". It is that the two tools disagree about what these
three assemblies contain, that GenomeX's channel has been checked against
constructed truth where CheckM2's number cannot be, and that adjudicating the
disagreement needs a third source this repository does not have.

## One genome the deeper set did resolve

`GCA_022041995.1` carried the highest marker duplication in the collection at
5.65%, against CheckM2's 2.37% — the one case where the marker signal looked
like it might be real. Most of it was paralogy *within* single contigs rather
than across them: cross-contig duplication was only 0.81%. Against the
lineage-specific set, total duplication falls to 2.18% and cross-contig
duplication is 0.87%, which puts GenomeX and CheckM2 within 0.2 points of each
other. The 5.65% was an artefact of scoring a Burkholderiaceae genome against a
marker set defined across all bacteria.

## Which set to use

`bacteria_odb10` remains the default, because GenomeX will not guess a lineage
and the universal set is the only honest choice when the lineage is unknown.

When the lineage *is* known, the deeper set is better on every measurement this
repository controls: finer contamination resolution, detection down to 2% on
constructed mixtures, and duplication figures that are not inflated by
out-of-lineage paralogy. It does not improve agreement with CheckM2, and it
costs 0.08 points of completeness agreement and about five times the scan time.

Pass it explicitly:

```bash
python -m genomex qc *.fna --lineage /path/to/burkholderiales_odb10 --outdir runs/deep
```
